# Private HLS execution foundation

Opt-in package only: no routes are registered, no existing path is changed, and
this is not the complete GPU-offload feature. `Supported()` advertises HLS and
ordinary segment seeks (including the local fMP4 init sentinel -1). All other
capabilities are absent. Placement must consult this before admitting work.

## Integration dependencies

- Mount `Worker` only on a private listener requiring verified client certificates.
  Its handler additionally requires TLS verified chains, a known boot-scoped peer,
  and explicit operation authorization, including status and media reads.
- Supply `Security.Authorize` backed by authoritative placement. Validate controller,
  worker boot, session, generation, grant and lease expiry against trusted state;
  never authorize a generation simply because the caller supplied it. Permit scoped
  stop/status reconciliation after expiry without permitting new media work.
- Supply `ResolveSource` backed by the source owner's grant authority. It must issue
  one exact worker-local `EncoderInputLease` and private literal-IP HTTPS range URL,
  bound to the identity and lifetime. It must prevent redirects and nested fetches,
  and revoke access when sealed. No caller InputURL, headers, commands, local paths,
  leases, channels or interfaces enter the wire. Caller loopback URLs are ignored.
  The backend's outbound HTTPS trust must accept the source certificate. Scope
  headers are generated by the worker-local lease, not sent over this protocol.
- Supply a dedicated `core.OwnedTranscoder` with adaptive ladders/governor, enhancement
  and automatic source mutation disabled. Do not share its session namespace with
  unrelated callers. Internal backend IDs hash the complete execution identity.
- Supply an HTTPS `http.Client` with `*http.Transport`, explicit roots, client
  certificate and `TLSClientConfig.VerifyConnection` binding the server to the
  intended worker boot. Certificate provisioning, renewal/revocation, placement,
  source grants, server HTTP limits/timeouts and durable reconciliation are external.
  The adapter clones the transport, disables proxies/redirects and requires verified
  TLS; plaintext is never an alternative.
- Supply a local decision function and verified hardware snapshot. These are injected,
  never discovered through this transport. Plan authorization must validate codecs,
  limits and all encoder choices against trusted placement/capabilities.

`StartHLSOwned` returns exact responsibility even on an uncertain start. The returned
`EncoderRetirement` is a `*Session`; call `Reconcile(ctx)` until there is terminal
proof. `RetireEncoder` requests exact retirement with a five-second RPC deadline;
`ErrEncoderPending`/`ErrUncertain` retain responsibility. Nil retirement requires
both successful backend encoder proof and input-producer proof. Terminal errors
retain the charge for external recovery. Transport loss and authority expiry never
supply proof. Use the owned API for integration; the legacy `StartHLS` signature
cannot return its extra responsibility token on error, though the adapter retains
it internally and `Stop(id)` still reaches pending execution.

Each start gets an initial authority lease of at most ten minutes
(`WorkerOptions.MaxLease`). Explicit authenticated fenced renewal can extend an
active lease as described below; a missing trusted validator disables renewal.
Expiry cancels pending work and retires the exact session, without inferring
successful retirement. Request cancellation seals late starts too. Media is
streamed directly, with backpressure, cancellation, HEAD, range/content/cache headers;
no media buffering, automatic retry, or local fallback is used.

The worker retains every record/tombstone for its entire unique boot lifetime;
capacity includes them, never evicts them, and fails closed when full. Duplicate starts
must match their original plan/grant/expiry. Stop-before-start seals that generation.
A higher generation cannot start while an earlier exact execution is unresolved;
stale stop/status use the old object and cannot retire its replacement. Worker restart
requires a fresh boot identity, making old requests invalid. Never reuse a boot ID.
The controller must retain unresolved old-boot responsibility across restart and
reconcile with durable placement; losing contact is not retirement proof. Adapter
records likewise live until adapter teardown. Teardown cannot be used to discard
unresolved ownership. Durable fenced retention/compaction is a subsequent increment.

## Explicit unsupported contracts

Starts reject DASH/HTTP Matroska, live/slate inputs, input headers and caller leases,
soft/burned/selected subtitles, external subtitle URLs, audio filter expressions,
enhancement, and nonserialized keyframe indexes before assignment. Remote `Probe`
and `SwapInput` return `ErrUnsupported`; source-change/release failover is unsupported.
Segment seeks delegate to the existing backend and may restart that exact encoder;
start-offset changes require retirement and a new authorized generation.

The session deliberately does not implement optional local contracts: DASHSession,
HTTPSession, SubtitleExtractor, ProbeLive/ProbeLiveWithHeaders, cached/streamed/soft
subtitles, Rungs/ServeRungPlaylist/ServeRungSegment, PrepareSwap/CheckSwap,
SwapInputBuffered/SwapWouldCopyVideo, CurrentSwapInput/WaitForReplacementOutput,
RecoveryBuffer, PlaybackState/Touch, IndependentSegments, Info/Decision/EncoderStatus,
Progress/GoodputKbps, HWAccelerated, SegmentDuration/RequestedPosition/Container/Protocol,
or manager-specific policy/capability/download/enhancement introspection. Consumers
must not silently substitute missing values or select workflows needing these.
`RequireIndependentProof` is sent unchanged to the backend, which owns playlist
independence claims. No Plex wire equivalence is claimed for unsupported workflows.

Next increment: durable placement/source-grant integration and fenced
retention, then explicit optional session contracts and source swaps, followed by
DASH/HTTP/subtitles/ABR, before application wiring or compatibility acceptance.

## Explicit lease renewal

The immutable Start includes its original grant and expiry. Its initial execution
lease has version zero. Renew is a separate operation, exposed through
`Session.Renew(ctx, Renewal)`; the parent drives renewal and `Reconcile(ctx)`.
There is no background polling or renewal goroutine in the adapter.

A Renewal carries the exact Identity, PreviousVersion, PreviousDeadline, an
absolute Deadline and Operation. Operation is the sequential next version scoped
to that identity, not an additive duration or a reusable arbitrary token. Zero and
uint64 overflow are rejected. Use UTC timestamps; equality compares exact
canonical instants, with no rounding/tolerance. The deadline must advance and be
within WorkerOptions.MaxLease of acceptance time. MaxLease remains at most ten
minutes per acceptance; timely successive renewals can support longer playback.

`WorkerOptions.ValidateRenewal` is optional and fails closed when absent: renewal
returns HTTP 422 / ErrUnsupported. Status Lease.Renewable reports configured
support; Supported() alone does not promise renewable playback. The callback is
mandatory before any extension, in addition to ordinary operation authorization.
It receives the immutable original Start and exact Renewal and returns a trusted
RenewalReceipt echoing that request. PlacementUntil and SourceUntil must each
independently cover Deadline. The receipt is not accepted from the wire.

The validator must check durable placement using its authoritative database clock,
all controller/worker boot and generation fences, and the authority of the SAME
source grant, URL and input lease through the requested new deadline. It must
actually extend or revalidate underlying source authority idempotently; it cannot
pretend the initial expiring URL grant remains valid, exchange the source, or
start a replacement encoder. If the source implementation cannot extend access
without changing input, renewal must fail. Missing database/source authority or
uncertain validation must fail closed. Validation runs outside the worker lock;
its placement/source updates may conservatively outlive a rejected worker
extension, but can never manufacture worker acceptance or retirement proof.

After validation, the worker locks and rechecks the old version/deadline,
execution state, stop, expiry, and policy bound before committing. Stop, expiry,
and renewal commit serialize under that same lock. A queued timer callback checks
its captured version AND deadline under lock, so Timer.Stop races cannot retire a
renewed execution. Renew never resolves a source or invokes an encoder. Starts
remain byte-immutable even after renewal.

The latest exact operation replay returns the accepted snapshot without another
extension or validation side effect. A changed payload at that version, or an
older retry after a newer acceptance, returns conflict (adapter ErrUncertain);
reconcile status instead. Concurrent exact retries converge on the same snapshot.
Status reports current accepted deadline/version/latest Renewal independently of
execution state and Stopped. An exact replay after stop/expiry may return history
but never clears Stopped or grants current authority; Session.Renew returns
ErrUncertain unless the observed execution is running and locally unstopped.
After a lost response, repeat the identical request or call Reconcile and inspect
Session.Lease(). Do not mint a later version until accepted history is known.

Worker deadlines use the worker clock; placement uses the database clock. The
trusted validator and deployment must apply a conservative clock-skew budget
before issuing a receipt and before treating authority expiry as safe reassignment.
This package does not invent a cross-host clock bound. Worker expiry requests
retirement; it does not prove the child/input have stopped. External placement
retirement still requires exact proofs, or its separately established safe expiry
policy. Integration must supply the validator, source extension mechanism,
parent-driven renewal schedule, and failure/reassignment policy before enabling
long-running remote playback. No application/core/config/placement wiring is
included here.
