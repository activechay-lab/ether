# Ether v0.3.5-rc.1

This is a release candidate for testing before the stable 0.3.5 release.

## Live TV and IPTV apps

- Xtream provider sources can supply movies and series as well as Live TV. Source setup, guide matching and credential handling share the Sources workflow. Refreshes preserve the previous healthy catalogue when a provider fails, and concurrent source edits or deletion cannot publish stale results.
- **IPTV apps (Xtream)** provides per-viewer, revocable logins for compatible IPTV players. Movies and episodes use Ether's normal catalogue, policies, resolver and byte-range playback; live channels use HLS. Switching to a movie after an idle live stream expires no longer fails admission.
- Owners can enable **Transcode for compatibility** for an individual viewer's IPTV channels, in addition to the existing channel setting. It uses Ether's configured transcoder and hardware availability. This is an explicit override, not automatic retry after a client decode failure.
- Compatible Live TV clients can retain HEVC; channel headers and provider identity survive playback routing, and delivered playback replenishes recovery attempts.
- Plex universal search can return permitted live channel names and numbers. Programme-guide text search is not added.
- Android Plex channel artwork requests support PNG/JPEG negotiation and the existing local artwork handling for a previous server connection address. The reported Fire Cube blank-column symptom still needs physical-device confirmation (#353).

## Catalogue, posters and Plex browsing

- Poster badges follow the selected rating sources and missing-rating policy, including a single selected badge (#349). Saving rating settings clears obsolete retry delays.
- Populated season pages refresh stale episode metadata, so a previously opened season can gain newly released episodes (#351).
- Related-title endpoints report totals and honor paging instead of presenting a truncated list as complete (#354).
- Catalogue AI interpretation applies filters together, shows progress and errors, and keeps results in the normal catalogue view.
- Release parsing recognizes additional multilingual metadata, and movie/show quality profiles can be scoped separately. Channel artwork has improved console presentation.

## Playback, diagnostics and recovery

- HLS FastStart preserves its authored ramp across worker replacement. Ramp encoding keeps the required frame order and preserves presentation timestamps when shifting DTS.
- Verified HLS output is published before final-byte delivery is acknowledged. Initial MPEG-TS discontinuity markers are accepted only on the first packet of each PID; later resets remain rejected.
- Private endpoint readiness waits for the current boot's capability publication. Displaced workers continue to reconcile after final Stop.
- Distributed recovery has explicit bounds for software H264/copied AAC, steady CPU H264 with re-encoded AAC, and verified closed-GOP H264/AAC remux. These are not a promise of recovery for arbitrary codecs, GOPs or hardware.
- Support captures include sanitized Plex playback request facts and effective limits. SQLite captures include allocated pages, reusable pages and the largest database objects, without exporting their row contents.
- Database integrity guidance and an owner-triggered recheck distinguish current findings from stale status.

## Upgrade and testing notes

- Back up the data directory, configuration and credentials key before upgrading. Cluster upgrades must follow the documented drain and version rules; mixed-version HA is not certified.
- Xtream provider connection admission remains process-local. Timeshift is not advertised by the Xtream frontend.
- Native GPU loss, physical-host loss and broad device compatibility must not be inferred from software-worker or offline tests. Consult the release acceptance record for the exact tested build and scope.
- A 48-hour accelerated SQLite workload starting near 610 MB reached about 660 MB, with only 64 KiB additional allocation on the second simulated day. It did not reproduce the reported 600 MB to 5.5 GB increase and does not establish that installation's cause. No automatic database compaction is introduced.
- Physical Apple TV validation is the next owner test for this RC. Existing client waivers and earlier fixture tests are not an exact-RC device certification. Report the app/version, playback mode and a fresh support capture with any failure.
