# Ether v0.3.10

Fixes for Stremio add-ons, dubbed releases from regional trackers, OpenAI models and Step aside.

## Fixes

- **Stremio add-ons: "Try again" works and health is real.** On a plain Stremio add-on (one installed from a link, such as USA TV Next or Torrentio), **Try again** failed with "Couldn't save, something went wrong", and an add-on marked **Not answering** could never recover from it. Ether was asking the add-on for Ether's own test and health endpoints, which Stremio add-ons don't have. It now checks an add-on the Stremio way, by reading its manifest: an add-on that answers is healthy, and one that doesn't is reported as not answering. An add-on still showing **Not answering** after updating recovers with one **Try again**.
- **Dubbed releases from a regional tracker show the dub's language.** A release named only `DUAL` or `MULTI` (for example `…WEB-DL.DUAL-C76` from a Brazilian tracker) says it has two audio tracks without naming the dub. v0.3.9 stopped guessing that track's language from the viewer's own language, so the detail page showed it as *Unknown*. Ether now uses the language of the indexer the release came from. Built-in sites that declare a language use it automatically, and any indexer can be given one under **Sources › Indexers › (indexer) › More options › Release language**. A pt-BR viewer then sees *Português (Brasil)* listed and preferred, and a pt-BR quality profile ranks those releases like ones tagged `PT-BR`. A language named in the release itself always wins, and Ether still never guesses the dub from the viewer's language.
- **OpenAI models can use tools.** With OpenAI as the language model, the AI in Collections and the assistant answered "This model can't use tools" on OpenAI's newest models. Those models only accept tools through OpenAI's Responses API, and Ether now uses it for OpenAI. When a provider does refuse tools, the message now includes the provider's own reason.
