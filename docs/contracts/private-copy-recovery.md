# Bounded private H264/AAC copy recovery

This adds real remux recovery; it never substitutes video or audio encoding.
Root alone integrates/releases. Existing 8cf runtime and evidence remain unchanged.

## Admission and source facts

Version 1 supports only complete MPEGTS sources, two streams: H264 at 25 fps,
no reordered frames, and stereo AAC-LC at 48 kHz / 1024 samples per AU.
Both streams must share a 90 kHz origin. Every 48 video frames must begin with
an IDR carrying SPS/PPS, exactly aligned with 90 AAC AUs. All cuts are 1.92 s.
The whole title must be an exact multiple of that grid, longer than one cut,
and at most 120 seconds. This deliberately does **not** admit ordinary unknown,
long, irregular-GOP, B-frame, open-GOP, partial-probe or unaligned sources.
Exact snapped-timeline recovery for those sources remains future work.

The source-role prober scans all packets and decodes all video frames through
its authenticated loopback source. Verification is optional, bounded by the
existing prober concurrency and overall deadline, a 10-second scan deadline,
32 MiB output budget, 10,000 packets and 120-second source duration. Any error,
decoder diagnostic, incomplete clock, missing IDR/headers or mismatched span
leaves ordinary playback available without this recovery proof. It records
packet payload/stream/PTS/DTS SHA256, counts, origin, grid, and actual keyframe
byte offsets. The source owner verifies the fact **and keyframe array** against
the pinned revision before issuing worker input. Prepared metadata equality is
also checked before placement. The transported fact alone is not authentication.

The additive `MediaInfo.CopyTimeline` field is omitted when absent and cloned
with media snapshots. `Capabilities.CopyTimeline` is negotiated explicitly.
Initial private authoring chooses 1.92 s only when no duration was requested;
an incompatible explicit grid is rejected for recovery. The immutable steady
ramp and copy-only single rendition survive worker configuration changes.
The original and replacement commands both use `-c:v copy -c:a copy`.

Automatic buffer eligibility, Tick detection, retirement, stable public delivery,
wire Resume validation, Manager Resume validation, and durable delivery-chain
validation use the same bounded profile. The delivery floor remains the sole
watermark; generation increments, lease fencing and exact old-worker retirement
remain unchanged. Recovery decisions retain keyframes explicitly because the
ordinary MediaInfo JSON intentionally omits that array.

## Pinned offline validation

Fixture: `internal/transcode/testdata/copy_recovery_h264_aac.ts`
SHA256 `aaaff790cfe0956b5607183191978370b0feb18719e52f56dbcc412b441cbfb9`.
It has 192 H264 frames / 360 AAC AUs / four 1.92-second segments, with 160x90
video and a synthetic 997 Hz sine. Generation with Jellyfin FFmpeg 8.1.3:

```sh
ffmpeg -f lavfi -i testsrc2=size=160x90:rate=25 \
  -f lavfi -i sine=frequency=997:sample_rate=48000 -t 7.68 \
  -c:v libx264 -threads 1 -bf 0 -g 48 -keyint_min 48 -sc_threshold 0 \
  -x264-params open-gop=0:repeat-headers=1 -c:a aac -ac 2 -b:a 128k \
  -f mpegts raw.ts
ffmpeg -i raw.ts -map 0:v -map 0:a -c copy \
  -bsf:a 'noise=drop=eq(n\,0)' -f mpegts source.ts
```

The second command drops only the AAC encoder's priming AU to construct the
explicitly aligned fixture; the runtime never repairs or rewrites source audio.
Use the committed fixture, not regenerated bytes, for the pinned gate.
